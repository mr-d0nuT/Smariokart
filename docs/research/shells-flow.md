# SMK 菜单流/标题画面/初始化链路 深读报告（shells / game-flow analyst）

> 来源：mk-main/src/recomp/smk_title.c（2961 行）、smk_init.c、smk_boot.c，对照 mk-main/docs/smk_flow_re.md。
> 所有地址均为 SNES 总线地址（bank:offset）；DP = 直接页 WRAM（本游戏 DP=0）；$xx 十六进制。帧率 60fps；时间常量均换算为帧数与秒。

## 0. 全局状态机骨架（boot → init → title → menus）

### 0.1 状态变量
| 变量 | 含义 |
|---|---|
| $36 | 当前模式（state） |
| $32 | 待切换模式（pending transition） |
| $48 | 亮度控制字：>0 淡入中，<0($8000 位) 淡出中，0=静止；$8F00=强制黑+淡出 |
| $015E | 淡入淡出步长（每帧增量），常规 **$0060** |
| $0160/$0161 | INIDISP 影子；高字节 $0161 每帧写 $2100；**$0160==$8000 表示完全黑屏** |
| $34 / $38 | NMI 帧计数器 / 游戏帧计数器（各 state handler 里 INC） |

### 0.2 主循环与 NMI 分发
- 主循环 `$80:8056`（每帧一次）：JSL $81:E067（转场编排）→ 清 NMI 标志 $44 → LDX $36; JSR ($8197,x) 调当前 state 主 handler。
- NMI `$80:8000`：INC $34 → JSR $80:B181（亮度/淡入淡出）→ JSR ($81BF,x)（per-state NMI handler）。
- **per-state init 表 `$81:E049`（按 $32 索引）**：
  00→E0AC  02→E126  04→E12E  06→E2F3  08→E13E  0A→E22B  0C→E388  0E→E390  10→E398  12→E258  14→E34F  16→E0AC  18→E136
- **转场条件（master sequencer `$81:E067`）**：$32 != 0 且 $0160 == $8000 才触发。流程：关 DMA/HDMA(420B/420C=0) → 旧状态存 $0106 → $36=0,$D0=0 → 关 NMI → JSR $F3AA 清理 → 调 E049[$32] init handler → **$48=$0001（启动淡入）** → $36←$32,$32=0 → 重开 NMI($4200=$B1)。
- ⚠️ recomp 的简化路径把 handler 挂到了自己的状态号上（$04→E0AD 标题、$06→E126 选人、$14→E398 模式选择），与真实表不完全一致（真表 02→E126、10→E398、04→E12E）。复刻 JS 版时建议按真实表语义理解屏幕归属。

### 0.3 实测 attract 流程时间线（smk_flow_re.md，无输入）
| 帧区间 | 时长 | $36 | 内容 |
|---|---|---|---|
| f1–126 | 126f (2.1s) | $00 | 黑屏 boot |
| f127–167 | 40f | $1A | 黑屏 init（WRAM 清零等） |
| f168–208 | 40f | $00 | 黑屏 |
| f209–1890 | ~1681f (28s) | $04 | **标题画面**（idle 计数器 $1040 数到 $0642） |
| f1891–1972 | 81f | $00 | 淡出进 demo |
| f1973+ | — | $02 | **attract demo 比赛**；demo 中按 START 回标题 $04 |

- 无独立 Nintendo logo 屏（©1992 印在标题图上）。recomp 开机直跳 $36=$04，省略了 00→1A→00 两段黑屏。
- 交互流程实测（snes9x/LakeSnes 双验证）：实走序列 `04→06(选人, f599)→08(排量/杯赛, f826)→02(比赛, f1045)`。
- **开机 WRAM 必须 0x55 填充**（已修在 LakeSnes snes.c）：$81:E46A 的游戏模式钳位读未初始化 RAM，垃圾值→2（1P+2P自动确认）；全 0 会卡死在选人界面等 P2 确认。

### 0.4 输入系统（`$80:843C / $80:8445`）
- 自动手柄寄存器 `$4218+x`（x=0 joy1, x=2 joy2）→ current 存 $20+x；**边沿 = (current ^ prev) & current** → 存 $28+x；prev 存 $24+x。
- 按键位（SMK 内部表示）：高字节 $0100=右、$0200=左、$0400=下、$0800=上、$1000=START、$2000=SELECT、$4000=Y、$8000=B；低字节 $0080=A、$0040=X、$0020=L、$0010=R。
  - 组合键实例：存档擦除 = Y+A+L+R 同按（(joy1|joy2)==$40B0，`$84:FD25`）。
  - 确认类输入统一判 **$9000=B 或 START**；取消=X($0040)。
- 软复位门（`$80:8445`）：仅当 $0E32≠0 且 $0E50==0 且 $32==0 且 B/START 边沿 → JML $80:85FD；稳态标题不会走到。

## 1. 初始化链路（boot → init）

### 1.1 复位向量 `$80:FF70`
SEI → XCE 进 native 模式 → 8-bit A/X/Y → 栈指针 S=$1FFF → **FastROM ($420D=1)** → JML $80:803A。

### 1.2 硬件初设 `$80:803A`
DB=$80；$4200=0（关NMI/IRQ）、$420B=0（关DMA）、$420C=0（关HDMA）、$2100=$8F（**bit7 强制黑 + 亮度15**）、$4016=0（手柄strobe关）、$4201=$8F（WRIO）→ JSL $81:E000。（force-interpret 模式下跑 ROM 原始 init——它包含 Mode7 光栅 HDMA 初始化 $81:F7F1→$FB7E，设置 $A4=6 与逐扫描线 M7 指针，比赛画面必需。）

### 1.3 完整初始化 `$81:E000`（顺序即依赖序）
1. **WRAM 清零**（JSR $E404）：$7E:2000-$7E:FFFF + 整个 $7F:0000-$FFFF memset/DMA。（SRAM 校验暂略）
2. **PPU 初设 + 字库 DMA**（JSL $80:8BEA）：OBSEL=$02（8x8/16x16 sprite，name base $4000）；MOSAIC/W12SEL/W34SEL/WOBJSEL/TMW/TSW/SETINI/CGWSEL/CGADSUB/COLDATA 全清零；TM=TS=$10（先只开 OBJ）；VMAIN=$80（word 访问，写高位自增）；VMADD=$4000；DMA ch0 ctrl=$1801（mode1 写 $2118/$2119）、src=$84:C500、size=$0400（1KB 字库 tile）→ VRAM $4000。
3. **APU 初始化**（JSR $F4D9）：经 $2140-$2143 握手（recomp 由 LakeSnes APU 代管）。
4. **DSP-1 复位**（JSR $E3EA）：向 $00:6000 连写 128 次 $80。
5. **sprite tile 解压 + 2bpp→4bpp 交错**（JSL $81:E576）：解压 $C7:0000 → $7F:4400（压缩流格式见 §5.1）；交错：每 tile 行 2 字节(平面0-1)后补 2 字节零(平面2-3)，8KB 源 → 16KB 输出到 $7F:A000-$DFFF；追加解压 $C4:0594 → $7F:8000。
6. **Mode7 角度表**（JSL $81:E4B3）：解压 atan 基表 $C6:1F46→$7F:0000(256B)，再建 **64×64=4096 字节角度表于 $7F:9000**（col≥row 用 atan2(row,col)，col<row 用镜像 0x40−atan2(col,row)）。atan2 用硬件除法算比值查表 + 象限修正表（negate $81:F7C3、offset $81:F7CB）。特殊值：Y=0 → X<0?$C0:$40；X=0 → 象限奇?$80:$00。
7. 收尾写关键 DP 变量：$48=$0F00 → **$36=$001A（初始 state！）** → CLI → **$4200=$B1**（NMI+自动手柄+V-IRQ）→ **$32=$0004（预约切到标题）** → $48=$8F00（强制黑+淡出中）→ $015E=$0060。

### 1.4 NMI 公共服务
- **亮度引擎 `$80:B181`（每帧）**：$48>0 淡入：$48 += [$015E]，≥$0F00 封顶并置 $48=0；$48<0 淡出：$48 −= [$015E]，下溢过 $8000（结果 bit15==0）时封底 $48=0、结果=$8000。结果写 $0160，其高字节 $0161 写 INIDISP $2100。**步长 $015E=$0060 ⇒ 全程淡入/淡出 ≈ 40 帧 ≈ 0.67 秒**（$0F00=3840 ÷ 96）。注意：标题主 handler $80:80BA 曾写过 $015E=$0040（原为存 $0162，随后被覆盖，无害）——以 $0060 为准。
- **OAM DMA `$80:946E`**：源 $00:0200（OAM 镜像 544B=$220）→ ch0 dest $2104，OAMADDR 先清 0。
- **逐条 sprite tile DMA `$81:CB35`**：处理 $0EA0 暂存缓冲（每项 6 字节：VRAM 目的 word、源偏移、源 bank、size_lo），**倒序**执行；VMAIN=$80、ch0 ctrl=$01 dest=$18($2118)、size_hi=0；结束清 $4A。
- 手柄读取 $80:843C 在 NMI cleanup $80:81B5 内调用（另有 APU 口同步 $2142/$2143）。

## 2. 标题画面（state $04）

### 2.1 转场装载链 `$81:E0AD`（DMA/VRAM 调用序列）
1. `$81:E50D` PPU 预设：OBSEL=$02；BG1SC=$00、BG2SC=BG3SC=BG4SC=$7B（map base=(reg>>2)*$400=$7800，64×32）；BG12NBA=$70、BG34NBA=$77；M7SEL=$C0；TM=TMW=$10；关 H/V IRQ($4207-$420A=0)、NMI/DMA/HDMA。
2. `$81:E10A`：解压 tile 数据 $C7:1996 → VRAM word $0000。
3. `$81:E118`：解压 tilemap $C7:0B29 → VRAM word $C000。
4. `$81:E584`：解压 $C4:0594 → VRAM word $8000。
5. **STZ $0E68**（标题输入门清零——著名的 $0E68 之谜：全 ROM 只有这一处 STZ，无静态 setter）。
6. 若 $0E32≠0（demo 回跳恢复子状态）：恢复 $2E←$0E3A、$2C←$0E3C、$30←$0E3E、$0150←$0E44、$1012←$0E40、$1112←$0E42 并清 $0E32。
7. **$85:8000 标题图形总装**：HDMA 表 + 8 个 sprite slot 初始化（配置表 $85:9059，每项 slot,X,Y,tile）；slot 字段 $18=X、$1C=Y、$2A=tile、$BA=$0140(哨兵)、$30=$0120、$44=targetY=Y，其余清零；DP $C8=$1000、$B0=$B2=$00B0。清 $10E2..$17E2（玩家 sprite flag）、$1F2A、$0E60。
   - **$84:F38C PPU 全复位**：关 HDMA/DMA → $2100=$80 强制黑 → 清窗口/色数学 → COLDATA=$E0(固定色黑) → 滚动寄存器 $210D-$2114 各双写清零 → OAM 镜像 $0200 全填 $E0F8（Xlo=$F8,Y=$E0 屏外）→ OAM 高位表 $0400 清 32B。
   - $84:FCF1 SRAM 校验和：sum($30:67F2..$67F5) vs $30:67F0，不符则清存档。
   - 4 块 sprite tile DMA（表 $85:81AA src / $85:81D0 size / $85:81F6 vram 目的，X=0,2,4,6；ch0 ctrl=$01 dest=$18，源 bank=$7F）。
   - VRAM $1C00 填 pattern $1C00 ×2048 words（BG3 map 清成空 tile），再 512 words $00FF。
   - **CGRAM 装载：512 字节（256 色）从 $7F:4000 → CGRAM $00-$FF**（调色板来自 E10A 解压缓冲）。
   - OAM 参数 $0300: $8054,$0C9D,$0C9D,$0C9D,$0C9D；显示 flag DP$85=$01；sprite 缓冲 $0300-$03FF 填屏外 $E0F8；模式字 DP$80=0（OAM build 模式）。终值：DP $8C=$3800、$8E=0、$62=0。
8. 最终 PPU 寄存器（源自 $85:8277 显示 flag 路径）：**BGMODE=$01（Mode 1）**；TM=$17（BG1+BG2+BG3+OBJ）；W12SEL=$22（BG2+BG3 用窗口1）；TMW=$03（BG1+BG2 窗口遮罩）；**BG1SC=$10→map $1000(32×32)；BG2SC=$15→map $1400(64×32)；BG3SC=$1C→map $1C00(32×32)**；BG12NBA=$00（tile $0000）；BG34NBA=$22（BG3/BG4 tile $2000）；OBSEL=$02；VMAIN=$80。
9. **窗口 HDMA ch1**：$4310=$41（indirect+2reg 写）、$4311=$26（目标 $2126/$2127=窗口1 左右边）、表址 WRAM $0180（13 字节拷自 ROM $85:82E2）、indirect bank=$85。表内容 {2C,09,83, 60,09,83, 28,09,83, 70,09,83, 00} → 44+96+40+112=292 行窗口恒为 **[左9, 右131]**（SNES px），整个可见区一个固定竖直窗口带（配合 TMW 做 logo 区遮罩）。
10. 清 $0158=0、$0E50=0。
11. `$81:E933`：解压 $C1:0000→$7F:C000，再两笔 64B DMA：$7F:D200→VRAM $5060、$7F:D2C0→VRAM $5160。

### 2.2 背景滚动 —— 精确参数 ⭐
- 每帧主逻辑 `$85:8045` mode0 路径第一步 $84:D1: INC $64（16 位）；NMI $80:8237 → $85:809B 把 DP $64/$65 低/高两次写 $210F（BG1HOFS）→ 开 HDMA ch1($420C=$02) → $81:CB35 sprite tile DMA。
- **⭐ 结论：标题背景水平滚动 = +1 SNES px/帧 = 60 px/s；BG2 map 是 64×32 tile ⇒ 水平 wrap 周期 = 512 SNES px = 1024 canvas px（2× 坐标系）。SNES HOFS 增大 ⇒ 图像视觉向左移动。**
- 我们的 JS TitleState 目前就是 60px/s 向左 + mod 512 回卷 —— 速度正确，但回卷周期应核对素材宽度（原版 1024 canvas px）。

### 2.3 logo 出现动画 / sprite slot 状态机（$85:8B7A）
- **只在 $48==0（淡入完成）后运行**。
- Y 插值引擎 $85:8EE9：轮询处理（DP $75 步进 0→$0E 每 2，到 $10 归零）——每帧只处理 1 个 slot：$1C,x 若等于 targetY $44,x 则 +1 否则 −1（围绕目标的 ±1px 振荡逼近）。
- 位置积分 $80:FE07：24 位位置（X: $17:$18:$19、Y: $1B:$1C:$1D）+= 16 位有符号速度（$22,x / $24,x），带进位/符号扩展。屏幕坐标 = pos − $FF00（即减 256）。
- tile 前进 $85:8F0B：$2A,x += $0800（切 VRAM 下一动画帧）。
- 表初始化 $85:8FB8：指针表 $85:9009/9013/901D/9027/9031/903B/9045/904F，每项 5 words（X,Y,tile,cfg,targetY）。
- **每 slot 相位切换的里程碑帧（slot 帧计数器 $40,x）**：

| slot | 里程碑帧 hex→dec | 相位数 |
|---|---|---|
| 0 ($1000) | D2→210, 1F2→498, 452→1106, 46A→1130, 53A→1338, 592→1426 | 6 |
| 1 ($1100) | 112→274, 232→562, 492→1170, 572→1394 | 4 |
| 2 ($1200) | 1F2→498, 217→535, 218→536, 23E→574, 302→770, 4C2→1218, 55A→1370 | 7 |
| 3 ($1300) | 152→338, 272→626, 4DA→1242, 54A→1354, 5BA→1466 | 5 |
| 4 ($1400) | 2FE→766, 422→1058 | 2 |
| 5 ($1500) | 4AA→1194, 568→1384 | 2 |
| 6 ($1600) | 192→402, 23C→572, 245→581, 2C2→706 | 4 |
| 7 ($1700) | 362→866, 3F0→1008, 472→1138 | 3 |

- 典型相位动作（速度=每帧加到 24 位位置的原始值，约 ±1~2 px/帧）：
  - slot0（主 logo/kart）：phase1 v=$0120(+288)；phase2 表初始化 + targetY/Y=$00C0(192)；phase3 v=$0200(+512)；phase4 tile=$3800、v=$0300(+768)、flag $86=$8000(H-flip)；phase5 v=0+下一帧。
  - 向左漂移速度值：$FED0(−304)、$FEB0(−336)、$FE90(−368)、$FEE0(−288)、$FDE0(−544) —— 巡游车队向左驶过。
  - 共享变量动画：slot2 phase2 $0284=$B028 → phase4 $0284=$F0E0（OAM attr 字切换）；phase3 起 $85:8F2E 循环：每帧 $0284+=3，计数器 DP$88++ 到 5 归零并在 **$0286=$3F02↔$3F04 切换（调色板/属性闪烁周期 = 5 帧 ≈ 12Hz）**；slot6 phase3 $0288=$F0E0；OAM 高位表 $0408=$AAAA。

### 2.4 OAM 构建 + 每帧 tile DMA（$80:8EC5→8F22 等价实现）
- 每帧先清 OAM 镜像（128 sprite 全 $F8/$E0 屏外）再重建：每个活动 slot 输出 **1 个 16×16 sprite**；tile 号 = (该 slot 的 VRAM 目的 − $5000)/16，VRAM 目的表 $80:846E = {$5800,$5840,$5880,$58C0,$5C00,$5C40,$5C80,$5CC0}（nt=1 页）；attr 保留 $2A,x 高字节的调色板/优先级位，强制 nt=1；$86,x bit15=H-flip(attr ^= $40)。屏外判定：sx>$FF 且 <$FF00 跳过。
- 帧数据变化检测（$30,x != $BA,x）→ 读 $80:9090[frame_ptr]：低字节=tile idx（查 $80:91FA 得源地址），高 nibble=行数 cnt、高字节&$F0=单次 DMA size；向 $0EA0+$4A 写 cnt 条目（vram+=0100/行，src+=0200/行），由 NMI $81:CB35 倒序 DMA 到 VRAM。

### 2.5 PRESS START / 输入与 demo 进入（$80:853D）
- 每帧：$015E=$0060；若 $32≠0（转场已预约）直接返回。
- **idle 计时器 $1040（sprite slot0 帧计数字段复用）≥ $0642（1602 帧 ≈ 26.7s）→ attract/demo 超时**（原版此路径同样 STA $32，A=$02 进 demo 比赛）。
- START（$1000，任一手柄 current 态）→ **$32=$0014 + $015E=$60 + $48=$8F00（淡出）** → 序列器进入 mode select。
- 原版还有 $0E68 门 + Select 组合判定（见 flow_re.md gate 章节）；recomp 简化为直接读 START。
- **输入门开启时机**：flow doc 实测标题输入在完全淡入（$0160=$0F00，约进入后 150 帧）后才生效——淡入期间按键被忽略。JS 复刻建议照抄这个「fade-in 完才收输入」的门。
- NMI 侧（$80:8237）：OAM DMA → BG scroll/HDMA（§2.2）→ audio/input cleanup $80:81B5。

### 2.6 存档擦除彩蛋（$84:FD25）
- 标题下同按 **Y+A+L+R（$40B0）** 进入擦除模式（$7B=1，从 $84:FDEA 拷 12 条文字 OAM 至 $03D0）；上下选 YES/NO（$7B=1/2），确认 YES 清 SRAM $30:6000-$67FF。$7B≠0 期间 $85:8045 主更新被短路。

## 3. 模式选择（GP / Match Race / Battle —— recomp state $14）

### 3.1 转场装载链 $81:E398
1. $C4:0000 解压 → $7F:0000；nibble 展开（$84:E378：64 行，palette byte | 像素 nibble，0 保持 0）→ $7F:7000；**DMA 4KB $7F:7000 → VRAM $3000（只写高位字节 dest=$19）**。
2. $EC5E 模式配置查找：$0126 = 表[$81:EC2F + $0124]。
3. **$81:E627 图形总链**：
   - E631：E68E（上步）→ **E6D4 多 bank 解压**（表 $81:EBA3/$EBEB/$EC03 按 1.5×$0126 索引 + 固定 $C1:12F8→$7F:D000；其中一块 nibble 展开 $7F:C000→$7F:4000 共 192 行）→ **E769 tilemap DMA**：$7F:4000 12KB → VRAM $0000（只写高位）、$7F:C800 4KB → VRAM $7000（mode1）、$7F:C000 1536B → $7800、碎片 $C100 768B→$7C00 / $C000 256B→$7D80 / $C500 256B→$7E00 / $C400 256B→$7E80。
   - $83:F2C3 模式专属 tile loader（recomp stub，按 $0126 查表 $83:F000）。
   - E63F：E745 **双重解压调色板**（表 $81:EB5B 按 3×$0124 索引 → $7F:C000，再 $7F:C000→$7F:0000）→ E7B5：**16KB $7F:0000 → VRAM $0000 只写低位字节**（VMAIN=$00 写低位自增）。
   - E72E：BG 配置表 $81:EBBB[1.5×$0126] → DF48 解压 → $7E:C000（内含 CGRAM 调色板）。
4. PPU 清理 + 字库 $84:C500→VRAM $4000 1KB 再 DMA 一遍 + OAM DMA。
5. **CGRAM**：DF48($C4:$1313→$7E:$3A80) 后 **DMA 512B $7E:$3A80 → CGRAM $00**。
6. **$84:F45A PPU：Mode 0**，TM=$1F（全部层），BG1SC=$24→map $2400、BG2SC=$28→$2800、BG3SC=$2C→$2C00、BG4SC=$38→$3800，BG12NBA=BG34NBA=$33（tiles $3000），OBSEL=$02，VMAIN=$80。

## 5. 数据格式附录

### 5.1 自定义解压流（$84:E09E → $7F；$84:DF48 → $7E，同一格式）
命令字节：$FF=结束；$E0-$FE=扩展命令（mode=(cmd<<3)&$E0，count=10位：(next byte | (cmd&3)<<8)+1）；否则 mode=cmd&$E0、count=(cmd&$1F)+1。
- $00 raw copy；$20 RLE 单字节填充；$40 双字节交替填充；$60 递增填充；$80 回引（16 位偏移 + 起始地址）；$A0 回引取反 XOR FF；$C0/$E0 近回引（1 字节负偏移；$E0 取反）。
- 输出基址 = VRAM word 地址（作为缓冲偏移）；DMA 由调用方另行执行。

### 5.2 nibble 展开（$84:E378）
每行：palette byte = src[row]；像素数据 src+$0100+row×32 共 32 packed 字节 → 64 输出字节（低 nibble 在前）：nibble≠0 ? nibble|palette : 0。

### 5.3 关键 WRAM 布局速查
| 区域 | 用途 |
|---|---|
| $0200-$03FF | OAM 镜像（128 slot × 4B：Xlo,Y,tile,attr）|
| $0400-$041F | OAM 高位表（X bit8 + size，每字节 4 sprite）|
| $0EA0 | sprite tile DMA 暂存（6B/项，$4A=写指针）|
| $1000+$100*n | 8 个 sprite slot（字段见 §2.3/§4.1）|
| $7E:C000 / $7E:$3A80 | BG 配置/CGRAM 暂存；模式选择调色板 |
| $7F:0000+ | 解压工作区；$7F:9000 M7 角度表；$7F:A000 4bpp sprite tiles |

## 7. JS 复刻建议（canvas 512×448，坐标 = SNES px × 2）

坐标系换算：SNES 256×224 → canvas 512×448，全部坐标 ×2。淡入淡出建议画一层黑色 overlay，alpha = 1 − brightness/15。

1. **转场编排器（最重要）**：做全局 transition = {pendingState, fadeDir}。确认键只设置 pending + 启动淡出；**必须等 fade 值降到 0（全黑）才真正 switch(state) 并执行该 state 的资源装载，然后从 0 开始淡入**。时长 40f/程（0.67s），与原版节奏一致。当前 JS 各 State 直接 Game.setState() 硬切，缺这套编排。
2. **标题背景**：速度 60px/s 正确；检查 wrap 周期应为素材实际平铺宽（原版 512 SNES px = 1024 canvas px）。CCSelect 的随机起始相位是自由发挥，原版每次从固定相位进。
3. **标题输入门**：淡入完成前忽略所有按键（原版行为，也防误触）；idle 26.7s 进 attract demo；demo 里按 START 回标题。建议补 DemoState（可复用 RaceState + 脚本化 AI 输入）。
4. **模式选择屏**：原版是「GP/Match/Battle 三选一」独立屏（我们把它合进了 TitleState 菜单）。若要还原：三行选项，Up/Down 移动（顺序 GP→Match→Battle），确认 = B/Start；光标是 4 枚横排小 sprite 组成的手掌图标（X 96..144、Y 随选项 96/112/128 → canvas 192..288/224..256），palette 6。
5. **选人屏**：8 角色 4×2 网格，左右 ±列、上下 ±行，**禁止落到对方玩家已选格**（2P 时）；**两段确认**——第 1 次按 accept → 锁人动画（卡丁车驶入/戴头盔），再按才最终确定，cancel(X/Esc) 可撤回第 1 段；双方定人后停 64 帧再转场（给特写动画留时间）；1P 模式 P2 自动确认；光标/名牌闪烁节拍 6 帧；移动与确认都要播 SFX；"CHOOSE YOUR DRIVER" 跑马灯两条不同速率（≈41/71 px/s）滚动。
6. **排量/杯赛屏（state $08）**：三个 shell 文件里没有它的实现（真表 $08→$81:E13E），是下一步 RE 的明确目标。已知它接收 $32=$0008、确认后进 $32=$0002 比赛。
7. **音频挂点**：光标移动/确认/取消统一走 $81:F5A7 入口的音效调用（现 JS 已有 sfx_menumove/menuselect，映射关系一致）。
8. **开机链**：BootState 目前 0.5s 假黑屏。要还原节奏可用：黑屏 2.1s → init 闪 40f → 黑 40f → 标题淡入 40f（约 3.4s 后标题可交互）。无需复刻 WRAM/VRAM 细节，但**时长节奏值得照抄**。
9. **不建议照抄的部分**：VRAM/CGRAM/DMA 细节是为真机渲染服务的；JS 直接用 drawImage/离屏 canvas 即可，只需保留「装载发生在黑屏期间」的时机语义（黑屏时预解码图片，避免切换瞬间卡顿）。
